# SEnuke AI Project Execution Builder Scope

## Purpose

The Project Execution Builder is the central workflow area of SEnuke AI. Its purpose is to turn website audits, keyword research, local SEO findings, AI content ideas, and social media plans into clear project tasks that a user can review and complete.

The goal is simple: users should not only see recommendations. They should know what to do next, why it matters, and where to take action.

## What It Solves

Today, SEO tools often show reports, scores, and suggestions, but users still need to decide what to do manually. The Project Execution Builder organizes all recommendations into one action plan.

It helps the user answer:

- What should I fix first?
- Which recommendations are most important?
- Which tasks can be generated by AI?
- Which tasks need manual work?
- Which tasks need approval before anything happens?
- What has already been completed?
- What still needs attention?

## Main Idea

Every recommendation becomes a task.

Examples:

- A missing page title becomes a task to write or apply a title.
- A broken link becomes a task to fix that link.
- A keyword opportunity becomes a task to improve or create a page.
- A local SEO issue becomes a task to fix a citation or review profile.
- A generated social post becomes a task to review and schedule it.
- An AI content output becomes a task to review and apply it.

## User Experience

The user opens a project and sees a clear execution plan.

The execution plan should show:

- Open tasks
- High-priority tasks
- Tasks that need review
- Tasks that are ready to complete
- Completed tasks
- Skipped tasks

Each task should clearly explain:

- What needs to be done
- Why it matters
- Which part of the platform created it
- Whether it can be automated
- Whether approval is needed
- Whether manual work is required
- The next button or action the user should take

## Project Dashboard Section

Each project should have an execution area with:

- A task summary
- A prioritized task list
- Filters by category, status, and priority
- Quick action buttons
- Links back to the related report, page, keyword, audit, or social post

The user should be able to mark a task as complete, skip a task, or open the related item.

## Task Categories

The first version should support tasks from these areas:

- Website audit
- Technical SEO
- Page optimization
- Keyword research
- Rank improvement
- Backlink and authority support
- Local SEO
- AI citation readiness
- AI content review
- Social media planning
- Manual business tasks

## Task Statuses

Tasks should use simple statuses:

- Not started
- Ready
- Needs review
- Approved
- Manual action required
- Completed
- Skipped
- Failed

## Automation Levels

Each task should show how much the system can help:

- Recommendation only
- AI can generate content
- System can prepare changes
- User approval is required
- Integration is required
- Manual work is required

This makes it clear what SEnuke AI can do automatically and what the user must still handle.

## Approval Rules

No external or irreversible action should happen automatically.

The user must approve actions such as:

- Publishing website changes
- Posting to social media
- Sending replies
- Registering a domain
- Updating DNS
- Sending outreach
- Applying CMS changes

For the first version, these actions can be shown as manual or approval-required tasks.

## First Version Scope

The first version should focus on organizing and tracking execution tasks.

It should include:

- A project execution task list
- Task creation from audit issues
- Task creation from keyword recommendations
- Task creation from local SEO recommendations
- Task creation from AI content outputs
- Task creation from social calendar posts
- Task filters and counters
- Task status updates
- Links back to the source item

The first version does not need to automatically publish, post, register domains, or connect to every outside platform.

## What Is Out of Scope for First Version

The first version should not include:

- Automatic website publishing
- Automatic social posting
- Domain registration
- DNS changes
- WordPress or Shopify updates
- Team assignments
- Complex task dependencies
- Recurring tasks
- Advanced notifications
- Full project management boards

These can be added after the basic execution workflow is working.

## Proper MVP Flow

The Project Execution Builder should follow one simple flow:

1. Create or select a project.
2. Add the project website and basic business details.
3. Run the website crawl.
4. Run keyword research for the main services or target keywords.
5. Add or review local SEO details when the business has a local market.
6. Generate AI content ideas or content drafts where needed.
7. Generate or prepare a social strategy when social promotion is part of the project.
8. Sync the execution plan.
9. Review the generated tasks.
10. Complete, skip, or open each task in the related module.
11. Re-run the crawl or reports after work is completed.
12. Use the updated score and task list to decide the next work cycle.

## Step-by-Step User Journey

Step 1: Project Setup

The user creates a project with a website URL. If the project is local, the user also enters business name, phone, address, services, and target locations.

Step 2: Website Crawl

The user runs a crawl. The system checks the website and finds technical SEO, page, content, indexability, and site file issues.

Step 3: Keyword Research

The user runs keyword research for important services or topics. The system stores keyword opportunities, ranking data, search volume, and page recommendations.

Step 4: Local SEO

The user reviews local SEO recommendations. The system can create tasks for profile gaps, citation issues, location targeting, service coverage, or local ranking improvements.

Step 5: AI Content

The user creates AI content drafts, page suggestions, meta content, FAQs, or article ideas. These become review tasks before anything is applied.

Step 6: Social Strategy

The user creates a social plan or calendar. Planned posts become review and scheduling tasks.

Step 7: Execution Plan Sync

The user opens the project health page and syncs the execution plan. The system collects recommendations from crawl, keyword research, local SEO, AI content, and social strategy.

Step 8: Task Review

The user sees one task list with priority, source module, status, impact, instructions, and an action button.

Step 9: Execution

The user opens each task, completes the required work, then marks the task as completed. If the task is not useful, the user skips it.

Step 10: Recheck

After completing work, the user reruns the crawl or related report. The new report shows whether the score, rankings, recommendations, or task list improved.

## Task Sources in First Version

The first version should create execution tasks from existing SEnuke AI modules:

- Website crawl issues become technical SEO and website health tasks.
- Keyword research runs become ranking improvement and content planning tasks.
- Local SEO recommendations become business profile and local visibility tasks.
- AI content generations become review and apply tasks.
- Social calendar posts become review and schedule tasks.

## What the User Should See on the Project Page

The project page should show:

- Project health score
- Latest crawl status
- Keyword research summary
- Local SEO summary
- Social strategy summary
- Execution Builder task counters
- Open tasks
- High-priority tasks
- Tasks needing review
- Completed tasks
- Buttons to open the related report or module

## Testing Flow

To test the first version:

1. Create a project with a real website URL.
2. Run a 150-page crawl.
3. Wait until the crawl is completed.
4. Open the project health page.
5. Confirm the crawl score and crawl history are visible.
6. Run keyword research for one or two target keywords.
7. Add local SEO details if the business is local.
8. Generate one AI content item.
9. Create or generate one social strategy.
10. Return to the project health page.
11. Click Sync tasks in the Project Execution Builder.
12. Confirm tasks appear from the available modules.
13. Open one related task.
14. Mark one task as completed.
15. Skip one task.
16. Refresh the page and confirm the task statuses are saved.

## Expected MVP Result

At the end of the first MVP flow, the user should not just see reports. The user should see a clear project action plan built from the reports and modules already inside SEnuke AI.

## Success Criteria

The Project Execution Builder is successful when:

- Users can see all project actions in one place.
- Recommendations from different modules become tasks.
- Tasks are prioritized.
- Users know what to do next.
- Users can track what is done and what is pending.
- No risky action happens without approval.
- The project feels like a guided workflow instead of separate tools.

## Simple Summary

The Project Execution Builder turns SEnuke AI from a reporting platform into an action platform.

Reports tell the user what is wrong.

The Execution Builder tells the user what to do next.
